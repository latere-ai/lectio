# API

## Overview

The HTTP surface a caller codes against: upload or name a file, submit
a parse, watch it, read the document whole or one object at a time,
cancel or retry. The contract is small on purpose. Every field it
accepts changes what happens; a field it does not implement is refused.

## Current state

The earlier service exposed `POST /v1/parse` with a result read by
polling, an upload endpoint, and an error envelope with stable codes.
The envelope, the idempotency header, the cursor scheme and the upload
limits are carried over. Four things are not: the result was a rendered
text with the layout hidden behind an unpublished route, several
request fields were accepted and did nothing, cancel recorded a state
without stopping work, and the event stream sent one snapshot. This
spec replaces those.

## Design

### Routes

All routes sit under a base path, `/v1` by default, set by
`LECTIO_BASE_PATH` so a deployment can mount the surface under a prefix
of its own. Probes (`/livez`, `/readyz`, `/version`) and
`/openapi.json` stay at the root.

| Method and path | Purpose | Action asked |
|---|---|---|
| `POST /files` | upload a source; `200` with the existing File on a content match | `file.create` |
| `GET /files/{file}` | File metadata | `file.read` |
| `DELETE /files/{file}` | delete the snapshot | `file.delete` |
| `POST /parses` | submit; `202` with the Parse | `parse.create` |
| `GET /parses` | list, filtered by `state`, `label.<key>`, `origin.path`, `file`, `created_after`, `created_before` | `parse.list` |
| `GET /parses/{parse}` | state, progress, usage, error | `parse.read` |
| `POST /parses/{parse}/cancel` | stop the work | `parse.cancel` |
| `POST /parses/{parse}/retry` | re-queue the tasks that did not succeed | `parse.create` |
| `DELETE /parses/{parse}` | delete the parse and every object it wrote; refuses a non-terminal parse | `parse.delete` |
| `GET /parses/{parse}/document` | the document; `?format=json` (default), `markdown`, `text` | `parse.read` |
| `GET /parses/{parse}/pages` | page list with state, without blocks | `parse.read` |
| `GET /parses/{parse}/pages/{n}` | one page with its blocks, readable as soon as that page succeeded | `parse.read` |
| `GET /parses/{parse}/pages/{n}/image` | the rendered page image | `parse.read` |
| `GET /parses/{parse}/blocks/{ref}` | one block | `parse.read` |
| `GET /parses/{parse}/fields` and `/fields/{name}` | extraction results | `parse.read` |
| `GET /parses/{parse}/chunks` | chunks as JSON lines | `parse.read` |
| `GET /parses/{parse}/events` | server-sent events | `parse.read` |
| `GET /readers` | the configured reader names and what each accepts | `reader.list` |
| `GET /usage` | meters ([[013-limits-and-usage]]) | `usage.read` |
| `GET /queue` | depth, running and pool state per group ([[006-fairness-and-priority]]) | `queue.read` |

### Submit

```json
{
  "source": { "file": "fil_01J..." },
  "origin": { "store": "example", "path": "reports/q3.pdf", "version": "4" },
  "pages": "1-3,7",
  "class": "interactive",
  "priority": 0,
  "reader": "default",
  "output": { "text": "markdown", "chunks": "section" },
  "extract": [
    { "name": "invoice", "schema": { }, "instructions": "", "citations": true, "required": false }
  ],
  "deadline": "10m",
  "reuse": true,
  "labels": { "batch": "2026-10" }
}
```

- `source` is exactly one of `{"file"}` or `{"url"}`
  ([[014-sources-and-retention]]).
- `origin` is provenance the caller supplies and Lectio stores, returns
  and filters on, and never interprets.
- `pages` selects pages; open ranges clamp to the document.
- `class` is `interactive` (default) or `batch`; `priority` orders the
  caller's own parses and is capped by the limits on the allow
  ([[006-fairness-and-priority]]).
- `reader` names a configured reader. Naming one pins it: the parse
  does not fall back to another ([[007-model-capacity]]). Absent, the
  routing policy decides.
- `output.text` is `markdown`, `plain` or `none`; `output.chunks` is
  `none`, `page` or `section` ([[010-assembly]]).
- `extract` is a list of named schemas ([[011-structured-extraction]]).
- `deadline` bounds the parse's wall clock from submit.
- `reuse` (default `true`) returns an existing succeeded parse of the
  same owner, the same content hash and the same options fingerprint
  instead of doing the work again. The answer is `200` with that Parse
  and `"reused": true`.
- A body with an unknown field, at any depth, is `400 unknown_field`
  naming the field.

`Idempotency-Key` makes a submit safe to repeat for 24 hours. The key
row and the parse are written in one transaction with a unique
constraint, so two concurrent submits with one key create one parse.
The same key with a different body is `409 idempotency_conflict`.

### Parse

```json
{
  "id": "prs_01J...", "owner": "https://issuer.example|alice", "group": "g_...",
  "state": "running",
  "class": "interactive",
  "file": "fil_01J...", "origin": { },
  "progress": { "stage": "reading", "pages_total": 120, "pages_done": 37, "pages_failed": 0, "waiting": "capacity" },
  "usage": { "pages": 37, "input_tokens": 412000, "output_tokens": 96000, "cost": "0.21", "currency": "USD" },
  "error": null,
  "created_at": "...", "started_at": "...", "finished_at": null,
  "trace_id": "..."
}
```

`state` is `queued`, `running`, `succeeded`, `failed` or `canceled`.
`progress.stage` is `queued`, `preparing`, `reading`, `assembling`,
`extracting` or `done`. `progress.waiting` says why nothing is moving
when nothing is: `turn` (other tenants are ahead), `capacity` (the
model pool is full or paused), or absent. A failed parse keeps every
page that succeeded, and its document is readable with the failed
pages marked.

### Events

`GET /parses/{parse}/events` streams `state`, `page` (one per settled
page, with its number and state) and `progress` events. Each carries a
monotonically increasing sequence as its id, and `Last-Event-ID`
resumes after it. Events are derived from rows by polling the database
on a short interval; there is no in-process bus, so any API replica
serves any stream and a restart loses nothing.

### Uploads

`POST /files` takes `multipart/form-data` or a raw body with
`Content-Type`. The body is streamed to the object store while it is
hashed; it is never buffered whole. The size limit is
`LECTIO_MAX_FILE_BYTES` (default 256 MiB) or the allow's lower figure.

### Errors

```json
{ "error": { "code": "queue_full", "message": "Too many parses are waiting. Try again shortly.", "detail": "group g_... holds 50 queued parses, limit 50", "retryable": true, "request_id": "req_..." } }
```

One code, one fixed sentence for a person in `message`, one sentence
for a developer in `detail`. Codes a caller branches on:

| Status | Codes |
|---|---|
| 400 | `invalid_request`, `unknown_field`, `invalid_pages`, `invalid_schema`, `unsupported_media_type`, `file_too_large`, `too_many_pages`, `source_unreachable` |
| 401 | `missing_token`, `invalid_token` |
| 403 | `forbidden`, `reader_not_permitted` |
| 404 | `parse_not_found`, `file_not_found`, `page_not_found`, `block_not_found`, `page_not_ready` |
| 409 | `idempotency_conflict`, `not_terminal`, `already_terminal` |
| 429 | `rate_limited`, `queue_full`, `budget_exhausted` |
| 503 | `authorizer_unavailable`, `store_unavailable` |

Failures of the work land on the parse, not on the submit:
`document_corrupt`, `page_unreadable`, `deadline_exceeded`,
`reader_unavailable`, `budget_exhausted`, `schema_not_satisfied`.

### Lists

Lists page by an opaque cursor over `(created_at, id)`, `limit` 50 by
default and 200 at most. The authorizer's `filter` narrows a list to
the owners and labels the caller may see.

## Not in this spec

A client library and a command line client; both follow once the
surface is implemented and are thin over it. Administrative writes
(changing a group's weight, pausing a pool) are configuration in the
first version ([[016-distribution]]).

## Acceptance criteria

| Criterion | Proven by |
|---|---|
| `api/openapi.yaml` describes every route, and a contract test fails when a handler and the document disagree | a test that walks the router against the document |
| Every documented request field changes observable behavior, and an undocumented field at any depth is refused | a table test with one case per field and a fuzz case for unknown fields |
| Two concurrent submits with one `Idempotency-Key` create one parse | a concurrency test against Postgres |
| `cancel` on a running parse ends the in-flight reader call within one heartbeat interval and no further page is read | an end-to-end test with a stub reader that blocks |
| A page is readable while the parse is still `running`, and the event stream delivers one `page` event per settled page, resumable by `Last-Event-ID` across an API restart | an end-to-end test |
| A failed parse returns the pages that succeeded, and `retry` reads only the pages that did not | an end-to-end test counting reader calls |
| An upload of the size limit completes with API heap growth under 32 MiB | a memory test |
| Every error response carries one code from the table and a `message` that passes the register check | a test over the error registry |
