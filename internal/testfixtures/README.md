## Signed containers

The two `.p7m` files are CMS SignedData structures with the content attached,
signed with a self-signed certificate made for this purpose and used for
nothing else. The signature is not meant to verify against any trust store.

## Files produced locally

The text files hold content that no test depends on beyond its format. The
`.doc` and `.rtf` files come from Apple's text system and the `.ppt`, `.odt`
and `.odp` files from LibreOffice, each converted from the OOXML fixture of the
same name. The
Keynote package keeps only its `Index/*.iwa` parts, which carry the slide.

## Generated office documents

`report.docx`, `ledger.xlsx` and `ledger.xlsm` are written by
`generate_test.go`, part by part, so that every construct the native
readers handle sits in a file whose content is known. Nothing in them
comes from a third party, and no name in them is a person's. A test
keeps each file equal to what generates it. To write them again:

```sh
go test ./internal/testfixtures -run TestGeneratedFixturesAreCurrent -update
```

The `.xlsm` holds no macro. The part a macro project is stored in is a
line of text, there so that the file is detected as a workbook with
macros.

The two `-libreoffice` files are the generated ones opened and written
back out by an office suite, which names parts, styles and formats its
own way. They are what proves the readers on a file no test author laid
out. Each was made in the conversion image of `deploy/converter`, with
the spreadsheet module added for the workbook, and with no network:

```sh
soffice --headless --convert-to 'docx:MS Word 2007 XML' report.docx
soffice --headless --convert-to 'xlsx:Calc MS Excel 2007 XML' ledger.xlsx
```

Writing the generated files again does not write these two again. They
change only when someone runs the suite over the new files and commits
what it wrote.
