## Signed containers

The two `.p7m` files are CMS SignedData structures with the content attached,
signed with a self-signed certificate made for this purpose and used for
nothing else. The signature is not meant to verify against any trust store.

## Files produced locally

The text files hold content that no test depends on beyond its format. The
`.doc` and `.rtf` files come from Apple's text system and the `.ppt`, `.odt`
and `.odp` files from LibreOffice, each converted from the OOXML fixture of the
same name. The
Keynote package keeps only its `Index/*.iwa` parts, which carry the slide.

## Generated office documents

`report.docx`, `ledger.xlsx` and `ledger.xlsm` are written by
`generate_test.go`, part by part, so that every construct the native
readers handle sits in a file whose content is known. Nothing in them
comes from a third party, and no name in them is a person's. A test
keeps each file equal to what generates it. To write them again:

```sh
go test ./internal/testfixtures -run TestGeneratedFixturesAreCurrent -update
```

The `.xlsm` holds no macro. The part a macro project is stored in is a
line of text, there so that the file is detected as a workbook with
macros.

The `-libreoffice` files are the generated ones opened and written
back out by an office suite, which names parts, styles and formats its
own way. They are what proves the readers on a file no test author laid
out. Each was made in the conversion image of `deploy/converter`, with
the spreadsheet module added for the workbook, and with no network:

```sh
soffice --headless --convert-to 'docx:MS Word 2007 XML' report.docx
soffice --headless --convert-to 'xlsx:Calc MS Excel 2007 XML' ledger.xlsx
```

Writing the generated files again does not write those again. They
change only when someone runs the suite over the new files and commits
what it wrote.

## A file written when it is asked for

`Logbook(pages, pictures...)` in `logbook.go` writes a PDF that carries
its text: a harbor log with one entry to a page, a heading, 2 paragraphs
and the page's number, set in the standard fonts, which a file names
and does not hold. The pages listed as pictures hold an image and no
text. It is no file of this directory: a test asks for the length it
needs, 300 pages are under 300 KB, and `LogbookEntry` says what each page
reads. Every sentence in it was written for this repository.

## The quality corpus

The files under `quality/` are documents whose content is known block by
block, so that what a parse returns can be scored against it
([`docs/quality.md`](../../docs/quality.md)). Everything in them was
written for this repository: every station, reading, name and number is
invented, and nothing comes from a third party. The corpus is 0.7 MB.

A truth, `<name>.truth.json`, lists the pages of a file and on each page
the blocks in reading order: the kind, the text, a table's cells with
their spans, and the box where the layout is known. `internal/quality`
reads it.

The survey is one HTML file. Each block of it is an element with a
`data-kind` attribute, in reading order, inside the page it is printed
on, and a script at the end of the file writes what those elements hold,
with the box of each on its page, onto the root element. Printing the
file gives the PDF, and reading the root element gives the truth, so the
2 cannot disagree. The truth records the SHA-256 of the HTML it was
measured from, and `TestQualityCorpusIsCurrent` fails when the HTML
changed and the truth did not.

To write the survey's PDF and truth again, name a headless Chromium:

```sh
CHROME=/path/to/chrome-headless-shell \
  go test ./internal/testfixtures -run TestQualityCorpusIsCurrent -update
```

Without `CHROME` the same command writes only what Go generates: the
presentation, and from `survey.pdf` as it is on disk the scanned PDF, the
PNG, the JPEG and the TIFF, each page rendered by the engine a parse
renders with. A PDF a browser prints carries the time it was printed, so
printing again changes the PDF's bytes and nothing a test reads.

`report.doc` was made once, in the conversion image of `deploy/converter`
with no network, and is not written again by any test:

```sh
soffice --headless --convert-to 'doc:MS Word 97' report.docx
```
